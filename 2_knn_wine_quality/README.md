# KNN на примере качества вина (Wine Quality)

**Файл:** `knn_wine_quality.ipynb`  
**Источник данных:** [Kaggle: Wine Quality Dataset](https://www.kaggle.com/datasets/yasserh/wine-quality-dataset)

Исследование алгоритма k-ближайших соседей (KNN) в задаче классификации: как масштабирование признаков, число соседей `k` и выбор метрики расстояния влияют на точность модели.

## О данных

Изначально планировалось использовать Ирисы, но они слишком «идеальные», поэтому выбран более жизненный датасет:

- **Размер:** 1143 записи;
- **Признаки:** 11 химических параметров вина (кислотность, сахар, хлориды, диоксид серы, алкоголь и другие);
- **Цель:** `quality`, экспертная оценка качества (от 3 до 8), то есть многоклассовая классификация.

Датасет загружается прямо из ноутбука через `kagglehub`, скачивать файл вручную не нужно.

## Что делается в ноутбуке

### 1. Первичный анализ
- загрузка данных, `head()` и `info()`;
- распределение целевой переменной (`countplot` по `quality`): классы несбалансированы, оценки в основном средние.

### 2. Подготовка данных
- удаляются столбцы `Id` и `quality` из признаков, цель берётся отдельно;
- разбиение на **train (80%)** и **test (20%)** с `random_state=42`;
- масштабирование **StandardScaler**: KNN работает на расстояниях, и без масштабирования признаки с большими числами (например, `total sulfur dioxide`) доминируют над мелкими (`chlorides`). Скалер обучается только на `X_train`, чтобы избежать утечки данных.

### 3. Baseline: без масштабирования и с ним
KNN с `k = 5`:

| Метод подготовки | Точность (Accuracy) |
| :--- | :--- |
| Без масштабирования | 0.5153 |
| С StandardScaler | **0.5590** |

Масштабирование дало прирост точности более чем на 4%.

### 4. Подбор числа соседей k
- перебор `k` от 1 до 50 на отмасштабированных данных;
- `weights='distance'`: чем ближе сосед, тем весомее его голос;
- график точности от `k` с отметкой лучшего значения.

### 5. Сравнение метрик расстояния
При `weights='distance'` сравниваются три метрики:

- **Manhattan (L1):** сумма модулей разностей;
- **Euclidean (L2):** расстояние «по прямой»;
- **Minkowski (p = 3):** сильнее штрафует крупные различия между признаками.

## Выводы

- Малые `k` дают низкую точность: модель запоминает отдельные примеры и принимает выбросы за правило (переобучение).
- Лучше всего себя показала метрика **Manhattan**: пик около 0.56, она быстрее выходит из зоны низкой точности. Euclidean уступает ей на 2–3%, Minkowski (p = 3) показала худший результат.
- Оптимальная конфигурация: **Manhattan, `k` в диапазоне 35–45, `weights='distance'`**.
