# Подбор гиперпараметров и интерпретируемость моделей

**Файл:** `hyperparameter_tuning_interpretability.ipynb`  
**Данные:** `Breast Cancer Wisconsin` из `sklearn.datasets`

Подбор гиперпараметров (Grid Search и Random Search) для SVM и Random Forest, а затем интерпретация моделей: Permutation Importance, PDP/ICE и SHAP. В конце смоделирована утечка данных, чтобы проверить, что интерпретация её обнаруживает.

## О данных

- **Задача:** бинарная классификация (злокачественная / доброкачественная опухоль);
- **Размер:** 569 объектов, 30 числовых признаков;
- **Разбиение:** train/test 80/20 со стратификацией (`random_state=42`): 455 и 114 объектов.

Датасет встроен в `scikit-learn`, скачивать ничего не нужно.

## Что делается в ноутбуке

### 1. Базовые модели
Три модели с параметрами по умолчанию, 5-fold кросс-валидация, метрика `f1_macro`:

| Модель | CV F1 (mean ± std) |
| :--- | :--- |
| SVM (с `StandardScaler`) | 0.9694 ± 0.0193 |
| Random Forest | 0.9504 ± 0.0255 |
| Logistic Regression (с `StandardScaler`) | 0.9787 ± 0.0139 |

### 2. Grid Search для SVM
`Pipeline(StandardScaler → SVC)`, сетка: `C` ∈ {0.1, 1, 10, 100}, `gamma` ∈ {scale, 0.01, 0.001}, `kernel` ∈ {rbf, linear}. Лучшие параметры: `C=10`, `gamma=0.01`, `kernel='rbf'`, CV F1 = 0.9786. Pipeline гарантирует, что масштабирование обучается только на обучающих фолдах (без утечки).

### 3. Random Search для Random Forest
`RandomizedSearchCV`, 50 итераций: `n_estimators`, `max_depth`, `min_samples_split`, `max_features`. Лучшие параметры: `max_depth=19`, `max_features=0.5`, `min_samples_split=4`, `n_estimators=356`, CV F1 = 0.9554.

### 4. Итоговое сравнение (тест используется один раз)

| Модель | CV F1 | Test F1 (macro) |
| :--- | :--- | :--- |
| SVM baseline | 0.9694 | 0.9812 |
| SVM Grid Search | 0.9786 | 0.9812 |
| RF baseline | 0.9504 | 0.9526 |
| RF Random Search | 0.9554 | 0.9526 |

### 5. Интерпретация лучшей модели (Random Forest)
- **Permutation Importance** на тесте и сравнение с встроенной важностью `feature_importances_`. По PI самый важный признак `worst concave points`, по встроенной важности лидирует `worst perimeter`: порядок топ-5 не совпадает;
- **PDP и ICE-кривые** для топ-3 признаков по PI;
- **SHAP:** `TreeExplainer`, summary plot, force plot для объекта, на котором модель ошиблась (из 5 ошибок на тесте).

### 6. Диагностика подозрительных признаков
К данным добавлены два искусственных признака: `leaky_feature` (таргет плюс небольшой шум) и `random_feature` (чистый шум).
- **PI** сразу выявляет утечку: важность `leaky_feature` около 0.26, а у остальных признаков близка к нулю;
- **SHAP** показывает чёткую зависимость: высокие значения `leaky_feature` сдвигают предсказание в плюс, низкие в минус;
- `random_feature` обнаруживается как шумовой: PI равна нулю, SHAP-значения сосредоточены около нуля.

## Выводы

- Тюнинг дал небольшой прирост CV F1 (SVM: 0.969 → 0.979, RF: 0.950 → 0.955), но на тесте результат не изменился: выборка маленькая, и модели уже близки к потолку.
- Встроенная важность и PI дают разный порядок признаков: сильно коррелированные признаки (`worst perimeter`, `worst area`, `worst radius`) делят важность между собой.
- PI и SHAP позволяют быстро находить утечки и шумовые признаки, а SHAP ещё и разбирать отдельные ошибки модели.
- Pipeline нужен, чтобы масштабирование не «подглядывало» в валидационные и тестовые данные.
